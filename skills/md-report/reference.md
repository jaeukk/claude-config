# md-report reference

Read this file for syntax. Read `example/main.html` and `example/visuals.js` for a working page that passes `verify.py`. Never read `template.html` or the scripts: everything a report needs is described here.

## Page skeleton (`main.html`)

`main.html` holds one `<main>…</main>`. `build.py` adds the head, header, contents rail, library and theme. Inside `<main>`:

- **Sections** are `h2`/`h3` with `id`s; the contents rail is built from them.
- **Key results:** `<section class="summary"><h2 id="key-results">Key results</h2><ul><li data-src="Note"><q>…</q></li>…</ul></section>`
- **Callouts:** `<aside class="callout note|caution|result" data-src="Note"><p class="label">Title</p><p>…</p></aside>`
- **Figures:** `<figure data-src="Note">…<figcaption>…</figcaption></figure>`. Figures number themselves, and `<main class="no-autonum">` turns that off when the notes number their own. Interactive figures use `figure.panel`. A wide SVG goes inside `<div class="scroll-x">`, so it scrolls on a phone instead of shrinking past legibility.
- **Other blocks:**
  - `dl.params` holds `dt`/`dd` pairs; `.cols` holds two cases side by side; `.cards` holds `.card` items.
  - A `.card` holds a `span.kicker`, a `span.big` and a `p`.
  - `details.more` takes a `summary` and folds long blocks.
  - `ul.tasks` takes `li.done` for completed items.
  - `blockquote`, `span.wikilink`, `span.cite` (`[key]`).
  - `div.flip` holds `figure data-tab="…"` children; readers switch between figures on shared axes.
  - `div.table-wrap` holds `table`; numeric columns right-align themselves.
- **Math** is TeX in `$…$`, `$$…$$` or `\begin{equation}`; MathJax renders it, and `--preamble` supplies vault macros. Axis, slider and SVG labels use Unicode, not TeX.
- **Images:** `<img src="{{files}}/name.png">`, with the file passed to `build.py --asset`.

## Provenance attributes (checked by `verify.py`)

| Markup | Meaning |
| --- | --- |
| `data-src="NoteA NoteB"` | The block rests on these notes (file stems). Its numbers, quotes, citekeys and formulas must occur in them, and the chip "from: NoteA, NoteB" is rendered from this same attribute. Inner elements inherit the nearest one. In a synthesis, every text block needs one. |
| `data-src="editorial"` | The report's own framing, visibly labeled "framing by this report". No numbers in prose. Use `<span data-src="editorial">$…$</span>` for a formula that is the page's own method rather than a note's. |
| `<span class="illustrative">0.4</span>` | A value the report chose (demo size, prefactor, slider default). It renders with ✱, and the block gets "✱ chosen by this report". This is the only exemption from the number checks. |
| `class="computed"` | Output computed live by the page (status lines, `livePlot` readouts). Exempt from the checks; the caption says it is computed. |
| `<q>` / `blockquote` | A verbatim excerpt of a scoped note, with `…` for cuts and the pieces in order. Matching ignores Markdown emphasis, wikilink brackets and whitespace, and it is case-sensitive except for an excerpt's first letter. Quotes generated by JS are checked too. |

**Formulas.** Every formula that states a relation (=, <, ≤, ∼, ∝, ≈, →, …) must be the note's own TeX, verbatim, macros included (`\vb`, `\abs`, `\frac`); only spacing is ignored. Copy it, don't retype it. A formula with no relation (a symbol, a term) is checked only for its numbers. In a synthesis, a formula with a relation or a number needs a `data-src` scope like any text.

**TeX inside JavaScript** is written with ``String.raw`…` `` (in a plain or untagged template string, `'\approx'` loses its backslash). `build.py` refuses any such literal that holds TeX, and `verify.py` checks the TeX that MathJax actually received for dropped backslashes (`TEXLOST`), which also catches forms the lint cannot see, such as a template nested in `${…}`.

**Plot text** (trace names, annotations, hover templates, axis and chart titles) is checked like prose against the plot's scope. Put computed values in a `livePlot` `readout`, never in labels.

## Charts from tables

`<div class="chart" data-table="ID" data-x="0" data-y="1,2" data-kind="line|scatter|bar" data-xlabel="…" data-ylabel="…"></div>`, with the table in `<details class="data"><summary>Data table</summary><div class="table-wrap"><table id="ID">…</table></div></details>` under it (add `open` when the table has columns the chart doesn't plot).

- Options: `data-logx`, `data-logy` (1-2-5 ticks; use them when values span more than 2 decades) and `data-lead`, which plots the first number of a cell like `0.4687 (10/10) → 0.4812`.
- A cell may carry its own `data-src`; the chip is ignored when the cell is read. A non-empty cell that does not parse fails a `check()`.
- Cell formats: `a ± b` plots an error bar, and `k/n` plots a fraction. A cell that fails to parse becomes a gap; then leave the table unplotted.
- Bar charts get a category x-axis.

## Atlas from a table

`<div class="plot atlas" data-table="ID" data-xlabel="χ" data-xrange="-0.02,0.82"></div>`

- The table's columns are **Category | Row | Values | Detail**. Detail is the hover text, so put the source wording there.
- Values are comma-separated: points `0.15`, ranges `0.20–0.35` (or `20%–35%`, as the note writes it), onsets `≳0.35` or `>0.33` (drawn as ▶), or `π/4`. A leading `≈` or `∼` is dropped.
- Use it when many studies report one shared parameter. The caption says they come from different systems and definitions.

## Concept map

```html
<script type="application/json" class="concept-map" id="cmap-spec">
{ "columns": [[{ "title": "", "nodes": ["Hub_Note", "Other"] }], [{ "title": "Group", "nodes": ["A", "B"] }]],
  "hub": "Hub_Note", "context": ["Linked_Context_Note"], "links": { "A": "#section-id" },
  "edges": [{ "from": "Hub_Note", "to": "Group", "label": "…" }, { "from": "B", "to": "A", "label": "precursor", "dash": true }] }
</script>
<figure data-src="editorial"><div class="scroll-x"><svg class="schematic" id="cmap" role="img" aria-label="…"></svg></div><figcaption>…</figcaption></figure>
```

In `visuals.js`: `conceptMap('cmap', 'cmap-spec');`.

- Nodes are note stems.
- An edge to a group stands for an edge to each of its notes. Every edge needs a wikilink between its two notes in either direction (`up:`, `related:`, body or "See also"); `verify.py` rejects any other edge.
- An edge from the report's own grouping takes `"editorial": true`, and the caption says so. Pass every node's note to `verify.py`.

## Live formula plots

```js
livePlot('plot-id', {
  formula: String.raw`\xi\sim\ell_t\,e^{\pi^2\ell_t/\lambda_e}`, src: 'Note',   // the note's TeX, verbatim
  sliders: [{ key: 'l', label: 'ℓt / λe', min: 0.2, max: 1, step: 0.05, value: 0.5, fmt: v => v.toFixed(2) }],
  traces: (p, th) => [{ x, y: x.map(v => …p.l…), mode: 'lines', name: '…' }],
  layout: (p, th) => ({ xaxis: { title: '…' }, yaxis: { title: '…', type: 'log' } }),   // titles as strings
  readout: p => `ratio ${…}`,   // optional: a computed value beside the sliders (class computed)
});
```

- `formula` is shown above the plot and must occur in the note's TeX (spacing is ignored). Implement exactly that expression.
- Slider ranges come from the note's stated ranges or bounds. A value the report chooses and states in the caption goes in `span.illustrative`.
- Define the plotted function once (`const f = …`), use it in `traces`, and add `check(cond, 'message')` that calls that same function against a value the note prints, a limit or an identity the formula implies. A check must fail when the function is changed; confirm that once by mutating it. `verify.py` reports failed checks.
- For custom Plotly figures, use `const th = plotTheme()` (`th.layout`, `th.axis({...})`, `th.config`, `th.tok('--s1')`) and push a draw function onto `redraws`, so the figure repaints on a theme change.

## Live demonstrations

Use a live demonstration only for a construction or rule a note defines (an optimization, a substitution rule), at small size, in `visuals.js`.

- Keep it under about 80 lines, finishing in about a second or animating with `requestAnimationFrame`.
- The caption states the method and size.
- Status lines it writes carry `class="computed"`.
- Add one `check()` per demonstration against a known property.

## Schematics (inline SVG)

- One figure states one claim. Draw the mechanism or the difference between two options, not boxes with names.
- Use `<svg class="schematic" viewBox="0 0 W H" role="img" aria-label="the claim">`, with color through `currentColor` or `var(--fg|--muted|--accent|--s1…)`. Never use literal colors.
- Label arrows with what flows. Each colored arrow gets its own `<marker>`. A label that sits on a line takes `class="halo"`.
- Use 11–13 px text and a grid for alignment.
- The caption starts "Schematic." Numbers on a schematic come from the notes, and shapes are otherwise qualitative.

## Chart rules (the parts of dataviz that apply)

- One measure per chart, never two y-axes.
- At most 3 series on a scatter plot and 8 on a line or bar chart.
- A legend whenever there are 2 or more series. Series colors follow the fixed token order `--s1`, `--s2`, …, which the template already supplies.
- Text uses ink colors, never series colors.
- Use a log axis when values span more than 2 decades.
- A table view always exists (`details.data`).

## Obsidian conversions

- **Frontmatter:** goes into `--meta`.
- **`button` blocks, `^block-id` anchors and HTML comments:** dropped.
- **`dataview` and `dataviewjs`:** evaluated once against the vault and shown as a static result, under a `p.meta` line saying it is a snapshot and naming the date it was evaluated for.
- **Wikilinks:** `[[path|alias]]` shows the alias; `[[Note]]` shows the note name.
- **`![[img.png]]`:** found with `find -L <vault> -name img.png`, then passed with `--asset`.
- **Several `#` headings:** the first is the title and every later heading moves down one level.
- **`\cite{key}`:** becomes `span.cite`.
- **Callouts:** `> [!type] Title` becomes an `aside.callout`.
- **`preamble:`:** pass that note to `--preamble`.
